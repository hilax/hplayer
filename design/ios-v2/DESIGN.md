# HPlayer iOS 界面重设计说明

本方案以 HPlayer 当前 SwiftUI 功能为依据，重新组织视觉层级、页面布局和入口。设计重点是让首页成为安静、清楚的个人观影片库：先看内容，再选操作；扫描、识别和授权等管理任务进入资源库或设置。原型中的影片、容量、文件大小、观看时间、任务进度和账号均为演示数据，不代表用户的真实片库。

本轮交付包含本地HTML交互原型、41张单页PNG，以及[线上Figma设计文件](https://www.figma.com/design/GokGdpKDY5nhYi9YnPRpx9)。它们表达同一套页面方案；原生App功能实现未改动。具体页面以本地索引和最终画板为准。

## 视觉方向

首页采用深色影院氛围：以影片背景建立第一眼印象，渐变承托片名和播放按钮，下面自然接续继续观看与海报货架。主视觉保留内容焦点，避免简介、评分、来源、技术参数、管理按钮同时争夺注意力。首页的大图属于用户片库精选，不暗示外部推荐服务。

资源库、搜索、设置采用更平静的页面底色、清楚的标题和统一行高。账号、来源、播放工具、库管理各自成组。轻量材质用于导航、浮层和少量操作，普通文件行和设置行保持清楚边界，避免每个元素都套玻璃卡片。

海报比例统一；电影和剧集展示片名与必要副信息，横版继续观看卡展示播放进度。图像加载失败时用稳定的中性占位，保留片名和点击区域。颜色用来强调播放与选中态，警告色留给真实失败或需要处理的状态；不把未识别文件塑造成首页警报。

字体以 iOS 系统字体和中文系统字形为实现目标。设计图中的字体是视觉参考，原生实现使用语义字号并适配动态字体。标题、正文、辅助信息保持明确层级；实际交互目标至少 44 × 44 pt，图标可小于点击区域。深浅色都应保留足够对比度，播放器始终使用深色。

核心页面使用真实电影、剧集海报和背景作样例，展示实际素材复杂度下的可读性与裁切效果。素材经Cinemeta元数据及相应图像服务取得，逐项记录在 [`assets/sources.json`](assets/sources.json)；影片样例不代表用户已拥有相应文件。

## 相比旧原型的具体改进

旧原型位于仓库 `prototype/`。本次改进以可见问题和功能真实性为依据，不以已有视觉审查中的所有建议作为已接受需求。

| 旧原型情况 | 本次处理 |
| --- | --- |
| 首页主视觉、继续观看卡叠放较密，海报下面缺少稳定的信息层级。 | 用明确的主视觉区域、货架标题与内容间距组织阅读节奏；片名、观看进度、主播放动作优先。 |
| “片库”页面实际以账号与工具入口为主，词义与海报片库容易混淆。 | 保留真实的资源管理语义，使用“资源库”，区分来源、本机文件、播放与云下载、媒体库管理。 |
| 首页与管理功能之间边界不清；旧审查还曾建议首页加入“待匹配”提醒。 | 以本次用户要求为准：首页不出现匹配提醒，管理任务统一进入资源库。旧审查的相反建议不采用。 |
| 旧资源库同时展示“封面匹配中心”和“扫描115全盘”，两个近似运维入口分散。 | 汇入“媒体库管理”，在该页表达扫描、识别、未匹配文件的关系，再进入具体任务。 |
| 旧播放设置页把“4K优先”“自动画质”“打开即横屏”等画成全局可设置项，并声称与播放器共享全部偏好。 | 以实际能力重画：倍速、音轨、字幕、画面等保留在播放上下文；不把不存在的全局设置当成功能。 |
| 旧原型出现多处 4K、HDR 等演示角标，以及同步时间、会员等资料。 | 技术标签只能在有可靠元数据时出现；无依据的状态不作为真实能力展示。演示数据须与真实接口数据区分。 |
| 旧原型覆盖以核心页为主，目录、批选、扫描、授权和错误状态不完整。 | 扩展到实际功能路径及必要浮层、表单和状态，避免仅交付漂亮首页。 |

## 首页规则：禁止展示匹配提示

这条规则覆盖首页的全部状态，不限于“待匹配封面”字样。

- 首页不展示待匹配数量、识别失败横幅、扫描进度条、匹配队列、重新匹配按钮、资料补全提醒，也不在 Tab 上为这些状态加提醒红点。
- 首页不展示“正在匹配封面”“暂未匹配到封面”“全盘扫描尚未完成”等管理状态。扫描和匹配在后台更新内容时，首页只自然更新已可展示的作品。
- 有已整理内容时：首页展示精选、继续观看、电影、剧集、演员合集等有效货架；没有内容的货架直接省略，不展示错误式占位。
- 首次空库时：首页提供简洁欢迎文案和添加视频、连接来源等现有入口，不以“匹配失败”解释空库。
- 已有文件但尚无可展示海报时：首页仍使用中性的片库空态，可保留继续观看，并提供“浏览资源库”。不出现未匹配计数、重试识别、进度或带有识别含义的说明。
- 扫描中、暂停、失败、已完成但仍有未识别文件时：首页沿用内容态或中性空态。具体进度、继续扫描和重试都在“资源库 → 媒体库管理”内。
- 修正封面属于作品管理。可通过作品操作菜单进入，避免把“匹配/换封面”作为首页精选区与“播放”并列的主动作。

源码核查：`HomeTab.swift` 中保留了 `pendingSection` 定义，但当前 `sections` 没有调用，故“待匹配封面”货架已不是当前显示来源。仍需在落地时迁走 `scanStatus`、`matchingState` 及首页管理入口，才能完整满足本规则。原型并不表示这些 SwiftUI 改动已经完成。

## 信息架构和主要流程

四个主要区域保持首页、资源库、设置、搜索的任务分工。本轮底部将“首页 / 资源库 / 设置”作为主组，搜索独立为右侧圆钮。系统版本对搜索Tab的原生形态有差异；实现时统一导航语义，并尊重iOS26独立搜索入口的系统表现。设计图中的栏位是布局表达，不承诺在所有iOS版本绘制相同的系统栏。

### 找片与继续观看

首页精选或电影海报 → 播放器。当前电影海报是直接播放，不强行增加电影详情页。继续观看卡 → 恢复原有来源并续播；卡片操作菜单可移除该观看记录。

首页剧集货架 / 剧集网格 / 搜索结果 → 剧集详情 → 选择季和集 → 播放器。详情主按钮根据已有观看记录续播，否则播放可用首集。作品条目显示真实集数和观看进度，不用“追更”或“已订阅”等未实现语义。

首页演员合集 / 搜索演员结果 → 演员作品网格 → 播放器。现有演员合集仅在至少两部不同作品满足数据条件时出现；不虚构演员传记、关注或外部作品目录。

### 添加与管理文件

添加 → 本地导入 / 115 文件夹 / 磁力播放。系统文件选择器承担实际文件选择，原型只表达入口和返回结果。资源库 → 本机视频 → 导入、播放、删除。

资源库 → 115 网盘 → 目录浏览 → 打开文件夹或播放视频。进入批选后，选中项目可播放或加入媒体库；目录支持名称、大小、修改时间排序、升降序、文件夹置顶。文案“加入媒体库”是对既有 `add...ToHome` 能力的清楚表达，不意味着新建下载副本。

资源库 → 媒体库管理 → 全盘扫描 / 选择文件夹 → 扫描进度、暂停与继续 → 未匹配影片 → 搜索资料并应用。已有文件在未识别时仍可从资源库播放。

### 搜索

搜索输入 → 片库即时筛选；提交搜索 → 请求 115 网盘。范围维持“全部 / 片库 / 115 网盘”。输入时的本地结果和待提交网盘查询应清楚区分。当前没有搜索历史存储，也没有网盘输入即搜能力；不把最近搜索、自动联想或防抖网盘搜索画成既有功能。

### 磁力与云下载

磁力播放 → 粘贴磁力链接或信息哈希 → 解析中 → 可播放文件列表 → 播放器。保留取消、失败重试、更换链接和最近播放记录。115 解析/中转入口按实际连接状态出现；不保证每个磁力链接能成功，也不把解析中自动开播当作已实现流程。

BT 云下载 → 必要时完成115官方授权 → 从手机导入 `.torrent` 或选择网盘种子 → 解析并选择文件 → 指定保存位置 → 创建115云下载任务 → 任务列表。它是保存到115网盘的任务，不是下载到手机的任务。现有保存位置含目标文件夹ID及相对路径输入；若后续改成完整目录选择器，应明确属于交互开发范围，不能仅凭画板认定已实现。

### 设置与授权

设置 → 115登录/重新登录/退出、外观、关于、开源许可。115网页登录与115开放平台官方授权是两条不同流程：前者用于网盘直连，后者用于相关云下载接口，不能合并成一个“已登录即已授权”的状态。

已有 TMDB Key、FANZA（DMM）凭证和115官方授权页面可以重新分组并增加设置页入口，这属于**入口迁移提案**，所调用能力已有。资料来源开关和凭证仍依照现有请求范围，不新增通用服务器管理。

## 真实功能边界

### 已有能力，允许重排入口

本地导入和播放、115直连登录与目录、首页海报整理、继续观看、电影/剧集网格、演员合集、剧集详情与分集、片库与115搜索、全盘/目录扫描、未匹配影片管理、手动资料匹配、可选资料源凭证、磁力解析与播放、BT云下载与官方授权、播放控制及外观切换。

### 播放设置的作用范围

- 播放器具备倍速、画质选项（仅片源实际提供时）、音轨、字幕、画面比例和缩放、解码、预缓存、定时关闭、截图、选集、旋转、锁定与诊断能力。
- 解码方式和预缓存时长确实通过 `VideoDecoding.saved`、`ReadaheadLevel.saved` 保存；可依照源码说明它们会被记住。
- 不能据此声称所有播放设置共享一份全局持久偏好。倍速、音轨、字幕、画面比例、缩放、定时关闭等按当前播放上下文表达；不额外承诺新视频、其他设备或重启后沿用。
- 当前不存在完整的全局播放偏好页。默认4K优先、自动画质策略、可调快进秒数、手势开关、自动横屏开关等，不作为已实现设置展示。
- 当前进入播放器会请求横屏；竖屏画板用于表达可用布局和旋转后的状态，不表示已有“默认保持竖屏”选项。

### 不纳入本轮既有功能原型

WebDAV、SMB、Emby/Jellyfin在当前代码中是禁用的开发中来源。它们不应有可用连接表单或成功状态，也不占首页位置。收藏、关注、追剧订阅、外部推荐、影片购租、弹幕、投屏、画中画、跨设备同步、云端账号系统、字幕在线搜索、私密空间及全局缓存管理，均不能因为竞品具备而被当成HPlayer已有能力。

独立电影详情、搜索历史、网盘自动搜索、批量修正匹配、删除后撤销等如需加入，应单独列为后续功能提案并估算实现；本原型不以视觉样式暗示这些能力已交付。

## 状态与手势注释

### 通用状态

| 场景 | 设计表达与动作 |
| --- | --- |
| 首次加载 | 保持标题、导航和内容骨架稳定，加载指示局限在对应区域；避免整个页面跳动。 |
| 图片未加载/失败 | 保留海报尺寸和片名，用中性占位；不把图片失败等同于文件不可播放。 |
| 空目录/无本机文件 | 说明当前没有文件，提供可用导入或返回动作；不展示扫描失败。 |
| 未连接115 | 显示连接入口，保留本机能力；搜索网盘和云下载说明对应前置条件。 |
| 请求失败 | 保留已输入关键词、目录或文件信息，给出重试；诊断细节置于专门入口。 |
| 扫描暂停/失败 | 在媒体库管理中显示保留的进度和继续动作；首页不呈现该状态。 |
| 搜索无结果 | 区分片库无结果与网盘无结果，允许修改关键词；不要用无结果表示尚未提交查询。 |
| 匹配无结果 | 保留文件名、搜索词和资料源，允许更换关键词；不可自动暗示文件已丢失。 |
| 播放缓冲/失败 | 保留退出、必要状态和重试；画质、音轨等选项随真实可用数据出现。 |
| 删除/移除 | 区分“删除本机文件”“从媒体库移除”“从继续观看移除”，三者影响不同。确认流程若新增，属于落地改进，不能声称当前已有撤销。 |

### 已有手势语义

| 手势/操作 | 当前行为和原型注释 |
| --- | --- |
| 首页主视觉左右滑动 | 切换精选；指示器与片名同步，播放动作作用于当前项。 |
| 货架横向滚动 | 浏览更多作品；“全部”进入对应网格，不能把整个货架误作单一点击目标。 |
| 长按海报/记录 | 打开该项操作菜单，按真实对象提供播放、匹配、移除/删除；首页主界面不因此出现匹配提醒。 |
| 播放画面单击 | 显示/隐藏控制层。 |
| 播放画面双击 | 播放/暂停；不照搬其他播放器的双击左右快进语义。 |
| 播放画面长按 | 临时3倍速，松手或取消后恢复原倍速。原生识别时长为0.6秒。 |
| 播放画面横向拖动 | 预览目标进度，松手提交；只在可拖动片源中有效。 |
| 播放画面左半侧竖拖 | 调节亮度。 |
| 播放画面右半侧竖拖 | 调节音量。 |
| 锁定 | 防止误触控制，保留解锁入口；面板打开时不同时处理冲突的画面拖动。 |
| 播放器设置/选集 | 在播放上下文内打开；窄屏与横屏都应留出明确关闭区域，选中态同时使用文字/图形而非只用颜色。 |

以上手势依据 `PlaybackGestureSurface.swift` 和 `PlaybackControlsView.swift`。双指缩放手势、字幕在线搜索等不因为参考图出现而被自动加入。

## 本地原型与线上Figma交付

本轮采用本地HTML构建页面，再捕获为Figma可编辑图层的方式交付，不交付SVG。

| 交付物 | 入口与用途 | 交互范围 |
| --- | --- | --- |
| 本地HTML原型 | [`index.html`](index.html)，由同目录样式、脚本和素材组成；可按页面浏览并切换总览。 | 提供导航、页面跳转、选项切换、表单示意及演示提示，用于检查流程和布局。 |
| 单页PNG | [`exports/`](exports/)，共41张；用于快速审阅、对照和归档。 | 静态图片，不含按钮事件或导航。 |
| 线上Figma | [HPlayer iOS设计文件](https://www.figma.com/design/GokGdpKDY5nhYi9YnPRpx9)，承载从本地HTML捕获的页面。 | 41 张独立可编辑画板，已配置 218 条跨页面跳转与首页、资源管理、播放器三个流程起点。 |

HTML中的交互是设计演示，使用样例数据，不接入用户真实115账户、不发起实际扫描或云下载，也不代表原生功能已经按新布局重写。HTML中可点击跳转，并不意味着这些JavaScript事件会随捕获自动成为Figma的Prototype连线。

Figma文件已创建，页面通过HTML捕获导入并在交付前检查。导入得到的文本、形状、图片与分组用于继续编辑；不应把这些图层直接称为已完成的设计系统、组件库、变量绑定或全部Auto Layout。已添加的 218 条关键流程连线用于 Figma 内的导航演示，不会改变 HTML 或原生 App 的真实能力。表单与选项状态仍以 HTML 演示为准。

对照和继续编辑时：

1. 先用HTML浏览完整页面与演示流程，再用41张PNG核对各状态的静态外观。
2. 在Figma中按页面名称查找对应画板，检查中文字体、字重、换行、海报裁切、渐变、透明度和底部安全区。尺寸按393 × 852或852 × 393核对。
3. 本地与Figma发生差异时，对照同名PNG定位捕获偏差，避免将字体替换或图片裁切差异误作设计变更。
4. Figma 已连接主要导航目标、返回与面板关闭，并配置可滚动内容区域；表单、选中态和主题切换等细节请在本地 HTML 中评审。
5. 原生实施前提取令牌并整理组件、Auto Layout与变量，复核深浅色、动态字体和不同屏幕宽度。这是后续设计工程，HTML捕获本身不会自动完成。

封面与背景的来源见 [`assets/sources.json`](assets/sources.json)，它们用于本次设计样例，不是HPlayer自有品牌资产。参考截图只用于设计研究，不作为HPlayer成品界面嵌入。

## 落地验收重点

- 首页所有状态均不出现扫描、匹配、待识别提示或管理数量。
- 每个可点击入口都有真实能力或明确标为后续提案；WebDAV等禁用来源不伪装成可连接。
- 电影直播放、剧集先详情、演员看已有作品的真实路径保持清楚。
- 搜索区分本地即时与网盘提交，不制造查询已发出的假象。
- 删除本机文件、移除库项、移除观看记录的文案准确区分。
- 播放控制尊重实际可用音轨、字幕、画质和可拖动性，不承诺全局持久设置。
- 115直连登录与官方授权分别表达；云下载任务明确保存在115。
- 原型文字、字体、海报比例、内容裁切、遮罩和底部安全区均经过最终视觉检查。
